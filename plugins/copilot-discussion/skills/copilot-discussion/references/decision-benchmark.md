# Jev决策对照（实验入口）

默认讨论仍是执行模式。只有用户明确要求对照时才使用测试入口 `tests/decision-benchmark.mjs`（完整源包中）。它不是MCP工具，也不应被自动当作正常讨论启动器。

A使用现有确定性控件选择，B额外调用配置的Jev决策模型选择相同允许控件；两者均由Jev Native执行，使用相同问题、等待与保存判定。运行顺序ABBA，每次新建专用页面/对话，两轮同题。记录worker启动、动作、决策调用、回答保存及总耗时；失败也保存。每种模式只有两个样本，不能据此给出普遍加速结论。

先核对实际配置的provider/model，复用现有凭据加载流程，不读取或打印env内容、不替换供应商。实验适配使用已配置Native运行时中的 `jev_ultrafast.model.choose` 与OpenRouter provider；新安装的官方纯执行运行时不保证包含这一额外provider适配，应先做无模型的导入/配置检查。凭据由配置的uv --env-file加载，不进入项目配置、页面或记录。命令示例仅供已配置决策环境使用：

```text
<uv启动命令> run --project <已配置Jev根目录> --env-file <凭据文件绝对路径，Windows用正斜杠> node <完整插件源包>/tests/decision-benchmark.mjs --scope synthetic --allow-paid --model <实际配置模型> --output <全新绝对目录>
```

此命令会付费调用模型，不能未授权执行。先合成页面，成功后才考虑真实Copilot。真实测试用scope copilot并加allow-authenticated-state，必须先告知实际接收服务、页面信息范围并获得用户授权。模型只接收专用测试会话的公开文本和允许控件，不含侧栏其他对话、截图或凭据。问题原文由宿主决定并精确填入，不调用文本生成辅助模型。

每个worker最多12次决策；通常两轮4次。模型必须选择允许的精确控件，并通过模型标识及置信度校验；BLOCKED、错误或低置信度停止，不猜测动作，不降低阈值强行通过。失败的付费运行不自动重试，若确需再次运行，先说明失败原因并请求新的授权。用户要求再次失败停止时，停止后续付费和真实测试。

本次v0.7验证中，两次合成尝试各调用一次Jev，第二次诊断返回BLOCKED、置信度0.34，未执行输入或发送；依用户条件停止，未执行真实Copilot对照。当前没有足够的成功B样本，不能判断开启决策是否更快，也不能把该适配失败推广到所有Jev任务。保持默认执行模式。
